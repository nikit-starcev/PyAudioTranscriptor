Краткие ADR по решениям, которые видны в коде и объясняют конструкцию. Формат:
контекст → решение → следствия. Источник — комментарии и структура кода.

## ADR-1. Движки за `typing.Protocol`, конвейер не зависит от реализаций

- **Контекст:** нужно менять движки ASR/диаризации/очистки, не переписывая
  конвейер; в тестах — подставлять заглушки.
- **Решение:** каждая стадия общается через `Protocol` (`SpeechRecognizer`,
  `SpeakerDiarizer`, `SegmentMerger`, `DenoiserProtocol`, `TextCorrector`,
  `ResultExporter`, `LlmClient`).
- **Следствия:** конкретную реализацию можно передать снаружи; используется в
  тестах (`pipeline.py:1-8`); фабрики (`create_diarizer`,
  `_build_recognizer`) выбирают реализацию по `AppConfig`.
- **Источник:** `transcription/base.py:17`, `diarization/base.py:19`,
  `merging/base.py:16`, `denoising/base.py:16`, `correction/base.py:11`,
  `export/base.py:12`, `llm/base.py:10`.

## ADR-2. Строго последовательный конвейер

- **Контекст:** ASR и диаризация конкурируют за GPU/CPU; параллелизм усложнил бы
  согласование времени.
- **Решение:** стадии выполняются последовательно, диаризация — только после
  ASR.
- **Следствия:** простая детерминированная модель прогресса/отмены; нет
  конкуренции за ресурсы внутри прогона. Sequence-диаграмма в README
  подчёркивает отсутствие параллелизма.
- **Источник:** `pipeline.py:627-733`, `README.md` (раздел «Архитектура»).

## ADR-3. Один фоновый воркер очереди

- **Контекст:** параллельный запуск задач только замедлил бы всех (общий
  GPU/CPU).
- **Решение:** `JobRunner` — один daemon-поток, задачи по одной.
- **Следствия:** предсказуемая нагрузка; отмена/осиротевшие задачи
  обрабатываются просто (`reconcile_orphans`); но пропускная способность ограничена.
- **Источник:** `web/runner.py:1-8`, `:152`, `:190`; `TODO.md:747`.

## ADR-4. Денойз первым и единый waveform

- **Контекст:** если ASR и диаризация видят разные версии аудио (денойзенное и
  исходное), временные метки разъезжаются.
- **Решение:** денойз идёт первым и отдаёт **один** очищенный файл обеим
  стадиям; общий 16-кГц waveform декодируется один раз (`_SharedWaveform`).
- **Следствия:** согласованные таймкоды; экономия декодирования. Кэш и ASR, и
  диаризации включает подпись фактического денойза.
- **Источник:** `pipeline.py:577-623`, `:109-136`; `:295-312`.

## ADR-5. Постадийный кэш с версиями реализаций

- **Контекст:** денойз/ASR/диаризация дорогие; повторные прогоны должны
  переиспользовать результат. Но при изменении логики/параметров кэш нельзя
  переиспользовать.
- **Решение:** ключ — SHA-256 от (версия формата, стадия, идентичность файла,
  параметры); в параметры входят версии реализаций (`ASR_IMPL_VERSION`,
  `DIARIZATION_IMPL_VERSION`, `HYBRID_IMPL_VERSION`,
  `SHERPA_DIARIZATION_IMPL_VERSION`, `SPEAKER_COUNT_ESTIMATOR_VERSION`).
- **Следствия:** смена модели/порогов/логики сбрасывает ровно нужный кэш;
  повреждённый кэш деградирует в пересчёт; отмена возобновляется с завершённых
  стадий.
- **Источник:** `cache/store.py:29,41,79-109`; `pipeline.py:315-489`;
  `pipeline.py:536-538`.

## ADR-6. Локальный сервер без аутентификации SPA; Bearer только для `/v1`

- **Контекст:** продукт задуман как локальная утилита; открытый наружу эндпоинт
  мог бы запускать обработку кому угодно.
- **Решение:** bind на `127.0.0.1`; SPA защищена только мягкой CSRF-проверкой;
  OpenAI-совместимый `/v1` требует строгий `Authorization: Bearer`.
- **Следствия:** простота и безопасность по умолчанию для личного режима;
  многопользовательский доступ требует отдельного режима
  ([`corporate-mode.md`](corporate-mode.md)).
- **Источник:** `web/app.py:3`, `:908`, `:1143-1191`, `:1171`;
  `cli/app.py:1413`; `TODO.md:745-746`.

## ADR-7. Корпоративные возможности — режим, а не форк

- **Контекст:** корпоративные требования (SSO, изоляция, RBAC) могли бы
  потребовать отдельной сборки/ветки.
- **Решение:** один репозиторий и одно ядро; корп-возможности включаются
  конфигом (`AUTH_MODE`), по умолчанию выключены; ядро не ветвится.
- **Следствия:** общие релизы/CI; сквозные швы узкие; риск — «утяжеление»
  веб-слоя, снимается MVP-объёмом.
- **Источник:** `TODO.md:718-724`.

## ADR-8. Внешние бинарники и модели не в артефакте

- **Контекст:** whisper.cpp/llama.cpp/nemo-speech/DeepFilterNet — нативные
  сборки под ОС/GPU; модели — гигабайты.
- **Решение:** portable/инсталляторы включают только `audio-transcriber`; движки
  и модели ставятся отдельно (реестр с sha256, скачивание из UI).
- **Следствия:** лёгкая и кросс-ОС упаковка; `doctor` показывает отсутствие как
  некритичное.
- **Источник:** `packaging/README.md:58-61`; `web/assets.py:220-418`;
  `models/catalog.py:64`.

## ADR-9. SPA на hash-роутах + catch-all на сервере

- **Контекст:** сервер раздаёт SPA и API с одного origin; CORS не нужен.
- **Решение:** клиентский роутинг на hash (`#/jobs/...`); серверный catch-all
  `/{full_path:path}` отдаёт статику или индекс, исключая `/api` и `/v1`.
- **Следствия:** нет конфликта API/SPA-маршрутов; deep-link работает без
  серверных rewrite-правил.
- **Источник:** `webui/src/app/routes.ts:1-11`; `web/app.py:985-999`.

## ADR-10. В web экспорт и резюме — по кнопке

- **Контекст:** стенограмма нужна сразу, а резюме может пересчитываться после
  ручных правок имён.
- **Решение:** в web `protocol_auto=False`: прогон готовит стенограмму, экспорт и
  резюме выполняются по запросу (`generate_protocol`).
- **Следствия:** правки имён попадают в протокол; `done` в web не включает
  запись экспорта; время до первого результата меньше.
- **Источник:** `web/config.py:385`; `protocol.py:1-11,94-128`;
  `pipeline.py:947-951`.

## ADR-11. GigaAM/гибрид ASR для русской речи; whisper.cpp Vulkan для старых AMD

- **Контекст:** целевое железо может быть без CUDA/ROCm (старые AMD); качество
  на русском важно.
- **Решение:** GigaAM v3 (RU) через `onnx-asr` без torch и гибридный ASR (#57,
  доработка «плохих» сегментов Whisper); whisper.cpp ускоряется через Vulkan.
- **Следствия:** работает без ROCm; ограничения (нет пословных меток у GigaAM,
  4 спикера у Sortformer) смягчаются/документируются.
- **Источник:** `transcription/gigaam_engine.py:1-9`,
  `transcription/hybrid.py:1-16`, `transcription/whisper_cpp_engine.py:1-9`;
  `docs/design/live-mode.md:22-24`.

## ADR-12. Мягкая деградация необязательных компонентов

- **Контекст:** отсутствие денойза/LLM/диаризации/enrollment не должно ронять
  прогон.
- **Решение:** каждая необязательная стадия при сбое логирует предупреждение и
  продолжает; кэш при повреждении пересчитывается.
- **Следствия:** устойчивость в «частично установленном» окружении; часть
  качества теряется без ошибки.
- **Источник:** `pipeline.py:82`, `:967-969`;
  `diarization/nemo_speech_engine.py:26-30`; `cache/store.py:8-9`.

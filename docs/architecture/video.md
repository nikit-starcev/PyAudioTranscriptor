# Анализ видеоряда (#121)

Исследование: извлечение **контента презентации** (слайды/схемы/текст → OCR) и **определение активного
говорящего** из видео.

- **[video-research.md](video-research.md)** — внешний ресёрч: кадры/детект сцен, OCR-движки (RU/EN, CPU),
  активный говорящий (ASD), аналоги, рекомендуемый стек, стоимость.
- **[video-integration.md](video-integration.md)** — интеграция в проект: варианты (стадия vs пост-шаг),
  модель данных, поток, кэш/память, UI/экспорт, риски, план.

## Ключевое

- **OCR слайдов — приоритет** (высокая ценность, на CPU осуществимо); **активный говорящий — опционально**.
- **Всё на CPU**: RX 590 (gfx803) без ROCm; у ONNX Runtime нет Vulkan EP → GPU-ускорения OCR/ASD нет.
- **Рекомендуемый стек:** PyAV (кадры; libavfilter уже есть) + детект сцен (PySceneDetect / ffmpeg `scdet`)
  → дедуп ImageHash (**+ кластеризация по OCR-Jaccard** — pHash/SSIM на шаблонных слайдах ненадёжны) →
  **RapidOCR** (onnxruntime, RU) + **Tesseract** фолбэк → привязка текста к таймкоду.
- **Активный говорящий:** лёгкий путь — MediaPipe Face Landmarker (blendshape `jawOpen`), тяжёлый —
  TalkNet / Light-ASD (torch, CPU дорого); плитка — **подсказка**, не переопределение диаризации.
- **Интеграция:** **опциональный пост-шаг по кнопке** (как «протокол»), **не** стадия конвейера; новый
  sidecar `*.slides/` + вкладка «Слайды»; зависимости — optional extra. Учесть: `StageCache` чистит
  только `*.json`/`*.wav` (картинки слайдов не эвиктятся — надо расширить).
- **Объём:** OCR-слайды — L (14–20 SP); +активный говорящий — XL. Связано с #47/#63 (диаризация),
  `memory.md` (слабое железо), #118 (упаковка внешних компонентов).

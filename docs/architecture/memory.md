# Память и слабое железо

Исследование потребления оперативной памяти и запуска на слабом железе (мало RAM, CPU без GPU).
Два документа:

- **[memory-analysis.md](memory-analysis.md)** — анализ по коду: где держится память, пиковые
  драйверы, рычаги оптимизации (с оценкой сложности), гид «слабое железо».
- **[memory-profile.md](memory-profile.md)** — эмпирический профиль: RSS Python и дочерних процессов
  по стадиям, прогоны «тяжёлый / лёгкий / CPU-only», где падает под ограничением RAM.

## Ключевое (кратко)

- **Память определяет ASR, а не длина файла.** whisper.cpp large: на GPU ~115 МБ RAM + ~1.55 ГБ VRAM;
  на CPU — ~1.82 ГБ RAM (и ~9× медленнее). `--device cpu` экономит ~435 МБ (torch не импортируется).
- **Пиковые драйверы (тяжёлый прогон):** модель ASR в процессе (faster-whisper ~1.6 ГБ), `llama-server`
  (~4.5 ГБ; почти всё — mmap весов), torch/pyannote. Лёгкий прогон (whisper.cpp base + sherpa, без
  LLM/денойза) — **~0.7–1.5 ГБ** → влезает в 4 ГБ.
- **Скрытый жир — waveform:** 16 кГц float32 = **230 МБ/час**; `_SharedWaveform` (`pipeline.py`)
  не освобождается и держится сквозь весь конвейер, плюс `whisper-cli` декодирует файл ещё 1–2 раза.
- **Изоляция уже частично есть:** `whisper-cli`/`llama-server`/`nemo-speech`/`deep-filter` — сабпроцессы
  (RSS уходит с процессом); pyannote/faster-whisper/GigaAM/sherpa живут в процессе (выгрузки нет).

## Ориентиры «слабое железо»

| RAM | Рабочая конфигурация |
|---|---|
| **4 ГБ** | whisper-cpp base/small + диаризация off (или sherpa) + без денойза/LLM |
| **8 ГБ** | whisper-cpp small/medium + sherpa/nemo + опционально лёгкая LLM (0.5–3B) |
| **16 ГБ** | large-v3-turbo + pyannote + 7B — но не всё одновременно |

Рычаги оптимизации (освобождение waveform, выгрузка моделей, лимит кэша, изоляция в сабпроцесс,
меньшие/квантованные модели) — в `memory-analysis.md` (§ «рычаги»).

## [0.5.7] - 2026-10-08

### Added

- **Генерация и управление API-ключом OpenAI-совместимого API из веб-интерфейса**
  (#110, расширение #48): эндпоинты `GET`/`POST`/`DELETE /api/api-key` — статус
  и действующий ключ, генерация случайного ключа с префиксом `sk-` (или
  сохранение своего, минимум 16 символов), очистка. Ключ хранится в
  `web-data/secrets.json` (права `0600`) и перекрывает `API_KEY` из
  `config.env`. Ключ перечитывается на каждом запросе `/v1/*`, поэтому
  сгенерированный в UI ключ действует сразу, без перезапуска сервера. В
  «Настройках» — карточка **«API-ключ»** (статус и источник, сгенерировать/
  перегенерировать, показать/скрыть, копировать, очистить с подтверждением).
  Ответы `/api/api-key` отдаются с `Cache-Control: no-store`, секрет не
  логируется.
- **OpenAI-совместимый API веб-сервера** (#48): `POST /v1/audio/transcriptions`
  (multipart; поля `file`/`model`/`language`/`prompt`/`response_format`/
  `temperature`/`timestamp_granularities[]`) и `GET /v1/models` (модель
  `whisper-1`). Форматы ответа `json`/`text`/`srt`/`vtt`/`verbose_json`. Режим
  синхронный: запрос создаёт задачу, запускает её и ждёт завершения (таймаут
  `OPENAI_TIMEOUT`). Строгая аутентификация по ключу `Authorization: Bearer
  <API_KEY>`; ключ задаётся в `config.env` (`API_KEY`) или
  `web-data/secrets.json`; без ключа эндпоинты отвечают `401`. Язык и
  начальная подсказка задачи сохраняются в записи задачи.
- **Новые форматы экспорта VTT, Markdown и PDF + пословная подсветка** (#53):
  экспортёры `VttExporter` (WebVTT), `MarkdownExporter` и `PdfExporter` (fpdf2,
  шрифт с кириллицей), формат `ExportFormat` (`vtt`/`md`/`pdf`), фабрика, CLI
  `--format`, список веб-экспорта и UI-селект «Формат»; подсветка слов в SRT/VTT
  при наличии пословных таймкодов (#45) — караоке-теги в VTT, `<font>` в SRT,
  флажок «Подсветка слов» и параметр `highlight` у `/api/jobs/{id}/export`.
- **Примерная оценка времени обработки при загрузке файла** (#107):
  `GET /api/files` отдаёт для каждого файла поле `estimate`
  (`seconds`, `by_stage`, `exact`, `has_history`) — оценка **до запуска** по
  длительности записи и RTF-весам завершённых прогонов (#15/#33). При
  отсутствии или неполном покрытии свежей истории берутся дефолтные веса
  стадий (учитывают устройство ASR — `cuda` быстрее; состав стадий — из
  текущих настроек: диаризация, денойз, LLM-резюме), а `exact=false` помечает
  результат как примерный. В панели «Файлы» рядом с длительностью —
  «≈ N мин», бейдж «примерно» и подсказка с разбивкой по стадиям.
- **Удаление бинарного пакета из раздела «Бинарные пакеты»** (#106):
  `DELETE /api/assets/{key}` удаляет каталог `web-data/bin/<key>/` и сбрасывает
  соответствующий путь в настройках; в UI — кнопка «Удалить» (с подтверждением)
  для управляемых бинарников.

### Changed

- **Fail-fast валидация LLM-конфигурации** (#9): `LLM_ENABLED=true` без модели
  (`LLM_MODEL` для локального `llama`) или без `LLM_BASE_URL`/`LLM_MODEL_NAME`
  (`openai`) теперь возбуждает `ConfigurationError` с подсказкой вместо
  предупреждения в рантайме.

### Fixed

- **«В очередь» не запускала задачу** (#109): `enqueue` создавал задачу со статусом
  `queued`, но не передавал её раннеру (`runner.submit` вызывался только в
  `/api/jobs/{id}/run`) — задача висела в `queued`, пока вручную не нажать «Запустить».
  Теперь `enqueue` после создания сразу вызывает `POST /api/jobs/{id}/run`. Найдено при
  E2E-тестировании интерфейса.

### Fixed

- **Docker (rootless/userns): chown ломал владельца bind-mount** (#104): `entrypoint.sh`
  определяет режим по `/proc/self/uid_map` и **не выполняет chown** при rootless (контейнерный
  root = хостовый пользователь), поэтому владелец хостового `./web-data` сохраняется (ранее
  хостовый сервер получал `OperationalError: attempt to write a readonly database`).
  `PUID`/`PGID` применяются только в rootful. Регресс-тест `tests/test_entrypoint_chown.sh`.

### Changed

- **Актуализация документации** (#102): README приведён к **Python 3.12+** (бейдж/«Требования»/
  macOS), денойз описан как внешний CLI `deep-filter`; добавлены разделы про новый UI
  (навигация, hash-маршруты, вкладки задачи), караоке, чат по стенограмме, очистку кэша,
  «Бинарные пакеты», разделение реплики/второй говорящий, промпты резюме и `PROTOCOL_AUTO`;
  дополнены таблица `config.env` и `config.example.env`.

## [0.5.5] - 2026-10-07

### Added

- **Пользовательские шаблоны промпта резюме** (#97): SQLite-хранилище
  (`storage/prompts_db.py`) с дефолтными шаблонами («Стандартный» = прежнее
  зашитое поведение, «Кратко», «Постановка задач»); REST CRUD

  панели протокола. Активный шаблон применяется к задаче при постановке и
  может быть переопределён телом `{"prompt_id": N}` у кнопки «Сформировать
  протокол». Новое поле `AppConfig.llm_summary_prompt` (env `LLM_SUMMARY_PROMPT`)
  прокинуто в `summarize_meeting` для всех вызовов (single/map/reduce).
- **Тумблер «Считать резюме автоматически по завершении» в веб-настройках**
  (#73): `protocol_auto` доступен в UI (раздел «Режимы обработки»), сохраняется
  через `PUT /api/settings` и мапится в `PROTOCOL_AUTO` конфигурации прогона;
  при выключении резюме/экспорт формируются только кнопкой «Сформировать
  протокол».

- **Интеграционные тесты на реальных моделях и бинарниках** (#11): каталог
  `tests/integration/` с маркером `integration` (по умолчанию исключён).
  `test_asr_whisper_cpp.py` и `test_asr_faster_whisper.py` проверяют непустые

  smoke-тест диаризации. Пути берутся из `config.env` или `INTEGRATION_*`; при
  отсутствии бинарника/модели/токена тест **пропускается** (не падает). Запуск:
  `pytest -m integration` (документация — `tests/integration/README.md`).

- **Разделение реплики между говорящими и второй говорящий на реплику** (#78): в редакторе
  стенограммы — режим «разделить» (реплика режется по границе: по пословным таймкодам, иначе
  пропорционально; каждой части — свой говорящий) и «+ второй говорящий» (наложение,
  `extra_speakers`, `speaker_label` «Имя1 + Имя2»). Ручные правки текста (#26) сохраняются,
  отмена — через общий undo. Эндпоинты `/api/jobs/{id}/transcript/split` и
  `…/transcript/extra-speaker`.

- **Чат/диалог по стенограмме с локальной LLM** (#54, вобрал #96): чат-панель в веб-UI,
  SSE-стриминг ответа, контекст из реплик задачи, цитаты-ссылки на реплики (таймкод +
  воспроизведение), история в SQLite (`storage/chat_db.py`). Эндпоинты
  `POST/GET/DELETE /api/jobs/{id}/chat`. Часть «ноутбук/календарь» — отдельно (#99).

## [0.5.4] - 2026-10-07

### Added

- **Всё внешнее — по кнопке: загрузка нативных бинарников из UI** (#98): новый реестр
  external assets (`web/assets.py`) — pip-пакеты + **бинарные архивы** (allowlist

  Компоненты: `deep-filter` (опц.), `llama-server` (Vulkan/Metal), `whisper-cli` (CPU);
  `nemo-speech` — инструкция (нет стабильного релиза). Эндпоинты `GET /api/assets`,
  `POST /api/assets/{key}/install`, `GET /api/assets/events`.
- **Сводка мастера первого запуска** (#98): `/api/setup` отдаёт `readiness` — модели,
  пакеты и бинарники с ✓/✗, размерами, путями и списками `missing_*`; UI обновлён
  (кнопки «Скачать»/«Установить» + прогресс, экран «Готовность»). `doctor` согласован;
  `deep-filter` помечен некритичным.

## [0.5.3] - 2026-10-07

### Changed

- **Денойз: внешний CLI `deep-filter` вместо Python-пакета DeepFilterNet** (#50, шаг 0):
  денойз выполняется Rust-бинарём `deep-filter` (DeepFilterNet v0.5.6), путь — `DEEP_FILTER_BINARY`
  с фолбэком `shutil.which`; модель встроена в бинарник. Снят блокер упаковки: у `DeepFilterLib`
  нет колёс >cp311, и он тянет `numpy<2` — из-за этого обходились костылём `--no-deps`. Память
  денойза снижена (чанковый режим, ~0.2 ГБ/час против ~1.15 ГБ), качество эквивалентно.
- **Поддержка Python 3.12–3.14** (#50, шаг 1): `requires-python = ">=3.12,<3.15"` (было `>=3.14`),
  снят единственный 3.14-only синтаксис (PEP 758 — `except A, B:` без скобок); CI — матрица
  Python 3.12/3.13/3.14.

### Added

- **Docker-образ (Linux x86_64, Vulkan)** (#50, шаг 2): `Dockerfile`
  (multi-stage), `docker-compose.yml`, `.dockerignore` и `entrypoint.sh`. Внутри
  образа — `whisper-cli` и `llama-server` с Vulkan (`llama.cpp` собирается из
  исходников), денойзер `deep-filter`, `ffmpeg`, torch **CPU** и extras
  `web`/`gigaam`/`sherpa`. Данные и модели — в томе `/data`; GPU — через
  `/dev/dri` (только Linux), веб-сервер работает от непривилегированного
  пользователя. См. README, раздел «Docker».

## [0.5.2] - 2026-10-05

### Fixed

- **Смена говорящего внутри реплики и короткие вставки** (#93): гибридный движок больше не
  отбрасывает локальных говорящих короче `min_speaker_seconds` (порог снижен до 0.5 с,
  `HYBRID_IMPL_VERSION` поднят) — короткие (~1 с) реплики другого спикера больше не теряются.
  Добавлено автоматическое **разделение реплики по смене говорящего** по пословным меткам
  (#45) с добором говорящего в «дырках» разметки и уверенностью по речи. На тестовой записи:
  «Да, я здесь» (Шленков) перестало приписываться соседу; реплик без говорящего 2 → 0.
- **Повторы-галлюцинации внутри реплики** (#94): очистка схлопывает соседние повторяющиеся
  n-граммы внутри одной реплики («все прекрасно. все прекрасно» → «все прекрасно»), не трогая
  легитимные заикания/числа; пословные метки синхронизируются.
- **Разрывы и дубли на стыках ASR-чанков** (#94): исправлена сшивка чанков whisper.cpp —
  перекрытие (2 с) дедуплицируется на уровне слов, разрезанное границей слово берётся целым
  (было 128 дублирующих слов на ~29 стыках).
- **Артефактные перекрытия соседних реплик** (#94): непомеченные пересечения подрезаются,
  реальное наложение речи (с `extra_speakers`) сохраняется.

## [0.5.1] - 2026-10-05

### Added

- **Пословные таймстемпы** (#45): слова с временами `start`/`end` и вероятностью
  собираются из токенов ASR (whisper.cpp — из полного JSON `-ojf`; faster-whisper —
  из его word-режима) с учётом офсета кусков и сшивкой слов на стыках. Доступны в
  JSON-результате и API (поле `words` у реплик), включены по умолчанию; флаг
  `--word-timestamps/--no-word-timestamps`, `WORD_TIMESTAMPS`, тумблер в вебе.

### Fixed

- **CLI наследует `config.env`, флаги — только явный override** (#76): `transcribe` без флагов берёт
  значения из `config.env` (как веб); `ASR_BACKEND`/`NEMO_SPEECH_*`/`PYANNOTE_LOCAL_MODEL` больше не
  перебиваются дефолтами. pyannote грузится офлайн при локальном пути и быстро падает на 401 (без
  зависания на HF-ретраях).
- **Зависание whisper-cli без таймаута** (#82): у вызова добавлен deadline
  (`WHISPER_CPP_TIMEOUT`, дефолт 3600 с; `0` отключает), stderr читается в
  фоновом потоке, по истечении процесс гасится (SIGTERM→SIGKILL) и стадия
  падает понятной `TranscriptionError` вместо бесконечного ожидания.
- **Кэш ASR/диаризации: настройка vs факт** (#83): в ключи входит фактически
  применённый денойз (а не `DENOISE`), ключ денойза — движок и его параметры
  (`chunk_seconds`/`overlap_seconds`/`output_sample_rate`), ключ диаризации —
  параметры маршрутизации/оценщика и все параметры гибрида. Версии
  `ASR_IMPL_VERSION` и `DIARIZATION_HYBRID_IMPL_VERSION` подняты.
- **Рассинхрон `text` ↔ `words` при правке текста** (#84): очистка артефактов и
  нормализация синхронизируют пословные метки с новым текстом (слова удалённых
  пометок выкидываются; при несопоставимости `words` инвалидируются).
- **Path traversal в отдаче статики SPA** (#79): catch-all `{full_path:path}`
  теперь разрешает путь и отдаёт файл только внутри каталога статики
  (`resolve()` + `is_relative_to`); `../`, `..%2f`, encoded и абсолютные пути
  получают `404`, а не файл хоста. Обычные ассеты и SPA-фолбэк сохранены.
- **OOM при HTTP Range для аудио** (#80): ответ отдаётся потоково

## [0.1.0] - 2026-09-30

Первый публичный релиз: локальная транскрибация аудио с разделением говорящих
и подготовкой стенограммы — полностью офлайн, без облачных API.

### Added

**Распознавание речи (локально, движок на выбор):**

- Два бэкенда ASR: `faster-whisper` (CUDA/CPU через PyTorch) и `whisper.cpp`
  (GPU через Vulkan — работает на AMD-картах без ROCm). Выбираются параметром
  `--asr-backend`.
- Чанкинг длинных записей в whisper.cpp: запись режется на куски ~30 с с
  перекрытием ~2 с, каждый кусок распознаётся отдельным вызовом, результаты
  сдвигаются по времени и склеиваются с дедупликацией. Настраивается
  переменными `WHISPER_CPP_CHUNK_SECONDS` и `WHISPER_CPP_CHUNK_OVERLAP`.
- Реальная длительность берётся из аудио; есть прогрев и прогресс по
  `fraction`.

**Диаризация и говорящие:**

- Определение говорящих через pyannote.audio, в том числе по локальной копии
  модели — полностью офлайн.
- Точное число говорящих (`--num-speakers`); в веб-интерфейсе — поле при
  постановке задачи в очередь (по умолчанию «авто»).
- Имена по образцам голоса (enrollment): сопоставление говорящих с именами по
  косинусному сходству и библиотека голосов.
- Перекрытия речи: при одновременной речи в реплике указываются все говорящие
  («Имя1 + Имя2») — из не-эксклюзивной разметки.
- Уверенность говорящего (`speaker_confidence`) и маркер
  `? [говорящий под вопросом]`.

**LLM-постобработка (локальный `llama.cpp`, Vulkan/CPU):**

- Правка терминов по глоссарию, резюме встречи в начале файла и
  экспериментальное определение имён (по умолчанию выключено); прозрачность
  промпта и деградация при нехватке видеопамяти.

**Глоссарий:**

- Текстовые файлы и SQLite-база (`glossary.db`) с источниками и терминами,
  импортом TXT/CSV и включением/выключением; подкоманда CLI `glossary`.

**Шумоподавление:**

- DeepFilterNet перед распознаванием и диаризацией, включён по умолчанию, с
  мягкой деградацией при недоступности движка.

**Качество стенограммы:**

- Разметка уверенности распознавания (`⚠`), схлопывание повторов, безопасная
  нормализация текста, пометка наложений (`⇄`), очистка неречевых артефактов
  (в том числе «голых» шумовых слов и шаблонных галлюцинаций) и опциональное
  автоисправление опечаток.
- Склейка подряд идущих коротких реплик одного говорящего в предложения.

**Экспорт и протокол:**

- Экспорт в TXT, DOCX, JSON и SRT с разметкой говорящих.
- Таймлайн «кто когда говорил».
- «Протокол» (резюме + стенограмма) формируется по кнопке; выгрузка
  стенограммы из веб-интерфейса.

**Интерфейсы:**

- **Веб-интерфейс** (`audio-transcriber web`; FastAPI + React SPA на
  `127.0.0.1`) — основной способ работы: очередь задач, загрузка и удаление
  файлов, число говорящих у задачи, живой прогресс по стадиям с длительностями
  и общим временем, стенограмма с поиском и метками, прослушивание фрагмента из
  реплики (HTTP Range), правка говорящих, «Применить имена», библиотека
  голосов, глоссарий, протокол, настройки и онбординг (баннер «Готовность» на
  основе `doctor`, авто-скачивание моделей, HF-токен как секрет, мастер первого
  запуска), светлая и тёмная тема.
- **CLI** на Typer: команды `transcribe`, `tui`, `web`, `glossary`, `doctor`.
- **TUI** на Textual: очередь, прогресс и поиск по стенограмме.
- Скрипты запуска `run.sh` / `run.ps1` / `run.bat` и `web.sh` / `web.ps1` /
  `web.bat`; Windows-обёртки синхронизированы с `run.sh`.

**Надёжность:**

- Постадийный кэш дорогих стадий (денойз/ASR/диаризация) и возобновление после
  сбоя: прогон, упавший на диаризации, при повторе переиспользует готовый ASR.
- `doctor` — самопроверка окружения, моделей и GPU-Vulkan (через
  `vulkaninfo`).

### Changed

- Версия хранится в единственном месте — в `pyproject.toml`; `__version__`
  читается из метаданных пакета, а не задаётся отдельно.
- TUI на Textual сохранён, но переведён во второстепенный путь: новые
  возможности развиваются в веб-интерфейсе.

### Fixed

- Чанкинг whisper.cpp устранён как причина потери текста и «шаблонных»
  галлюцинаций на длинных записях.
- Убрано лишнее перекодирование подходящего WAV (round-trip), из-за которого
  терялись куски аудио.
- Aligner больше не «угадывает» говорящего вслепую на больших разрывах
  разметки.
- При старте веб-сервера выполняется реконсиляция «осиротевших» задач очереди.
- История SSE очищается при повторном прогоне задачи.

### Architecture

- Движки вынесены за протоколы (`typing.Protocol`) для ASR, диаризации,
  объединения, экспорта, LLM и денойза — реализации взаимозаменяемы.
- Конвейер сборки и порядок вызовов — в `pipeline.py` (последовательный).
- TUI-приложение декомпозировано на модули (экраны, виджеты, сообщения,
  очередь, сборка конфигурации).
- Доменные модели не зависят от конкретных движков.

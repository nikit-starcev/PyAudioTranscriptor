## [Unreleased]

### Added

- Обработанные файлы убираются из списка «Файлы» (#16): после успешного
  прогона исходник помечается sidecar-маркером `<файл>.processed` и
  исключается из `GET /api/files`, оставаясь на месте — аудио
  (`/api/jobs/{id}/audio`), повторный запуск и стадийный кэш не затронуты.
  `GET /api/files?include_processed=true` показывает обработанные (поле
  `processed`), `POST /api/files/{name}/restore` возвращает файл в основной
  список; `DELETE /api/files/{name}` снимает маркер. Ошибочные и отменённые
  прогоны файл не убирают. В веб-интерфейсе — тумблер «Обработанные», бейдж
  «Обработан» и кнопка «Вернуть».
- Сводный процент выполнения и «здоровье» задачи (#24) и прогноз длительности
  стадий — ETA (#15). API/SSE задач отдают `progress_percent` (по весам стадий
  из медианных RTF завершённых прогонов; кэш-стадии ≈ мгновенны),
  `eta_seconds`/`eta_by_stage` и `health: {status, last_update_seconds}`
  (`ok`/`slow`/`stalled`; осиротевшие `running` без активного воркера —
  `stalled`). Длительность аудио пробуется при старте задачи, поэтому ETA
  доступен уже во время прогона. В веб-интерфейсе под прогрессом — общий
  процент, бейдж здоровья, «≈ осталось N мин» и «последнее обновление N назад»;
  счётчики «тикают» между событиями SSE.
- У задач появилось поле `updated_at` (в `web-data/jobs.db`, с авто-миграцией) —
  давность последнего обновления для оценки «здоровья».
- Несколько вариантов прослушивания говорящего (#25): `GET
  /api/jobs/{id}/speakers/{speaker_id}/variants` возвращает до 5
  неперекрывающихся окон `[{start, end, duration, score}]` (лучшие по энергии
  чистой речи; без доступного аудио — самые длинные реплики). В панели
  «Говорящие» появился раскрываемый список вариантов: время `[start–end]`,
  длительность, ▶ на каждый (окно исходного аудио через существующий
  Range-эндпоинт) и сохранение выбранного варианта в библиотеку голосов.
- Несколько образцов голоса на одного человека (#19): файлы библиотеки
  группируются по базовому имени (`Иван.wav`, `Иван (2).wav`, …), загрузка и
  `save_speaker_sample` добавляют новый образец вместо перезаписи, удаление
  доступно по файлу и по человеку. `GET /api/voices` отдаёт сгруппированный
  список, `VoicesModal` показывает группы с раскрытием и ▶ на образец, а
  «Применить имена» усредняет **все** образцы человека.
- Настраиваемые гиперпараметры диаризации: `--min-duration-off` (паузы короче
  значения склеиваются внутри реплики; наш дефолт — 0.5 против 0.0 у pyannote,
  заметно меньше дробления), `--clustering-threshold` и `--clustering-fb`
  (грубые рычаги числа говорящих). Применяются через `pipeline.instantiate`
  после загрузки модели; меняют ключ кэша диаризации.
- Диапазон числа говорящих: `--min-speakers`/`--max-speakers` (CLI, `config.env`,
  веб-интерфейс). Точное `--num-speakers` приоритетнее диапазона.
- В веб-интерфейсе у задачи добавлены поля «мин»/«макс» говорящих рядом с
  точным числом; отдаются/принимаются `POST/PATCH /api/jobs` и хранятся в БД.
- Раздел «Запуск на macOS» в README: что работает из коробки (CPU-пайплайн
  `faster-whisper` + диаризация, `afplay`, `DYLD_LIBRARY_PATH` в `doctor`) и
  что требует отдельной сборки (нативные `whisper.cpp`/`llama.cpp` под Metal,
  отсутствие CUDA, `notify-send` и денойз).

## [0.1.0] - 2026-09-30

Первый публичный релиз: локальная транскрибация аудио с разделением говорящих
и подготовкой стенограммы — полностью офлайн, без облачных API.

### Added

**Распознавание речи (локально, движок на выбор):**

- Два бэкенда ASR: `faster-whisper` (CUDA/CPU через PyTorch) и `whisper.cpp`
  (GPU через Vulkan — работает на AMD-картах без ROCm). Выбираются параметром
  `--asr-backend`.
- Чанкинг длинных записей в whisper.cpp: запись режется на куски ~30 с с
  перекрытием ~2 с, каждый кусок распознаётся отдельным вызовом, результаты
  сдвигаются по времени и склеиваются с дедупликацией. Настраивается
  переменными `WHISPER_CPP_CHUNK_SECONDS` и `WHISPER_CPP_CHUNK_OVERLAP`.
- Реальная длительность берётся из аудио; есть прогрев и прогресс по
  `fraction`.

**Диаризация и говорящие:**

- Определение говорящих через pyannote.audio, в том числе по локальной копии
  модели — полностью офлайн.
- Точное число говорящих (`--num-speakers`); в веб-интерфейсе — поле при
  постановке задачи в очередь (по умолчанию «авто»).
- Имена по образцам голоса (enrollment): сопоставление говорящих с именами по
  косинусному сходству и библиотека голосов.
- Перекрытия речи: при одновременной речи в реплике указываются все говорящие
  («Имя1 + Имя2») — из не-эксклюзивной разметки.
- Уверенность говорящего (`speaker_confidence`) и маркер
  `? [говорящий под вопросом]`.

**LLM-постобработка (локальный `llama.cpp`, Vulkan/CPU):**

- Правка терминов по глоссарию, резюме встречи в начале файла и
  экспериментальное определение имён (по умолчанию выключено); прозрачность
  промпта и деградация при нехватке видеопамяти.

**Глоссарий:**

- Текстовые файлы и SQLite-база (`glossary.db`) с источниками и терминами,
  импортом TXT/CSV и включением/выключением; подкоманда CLI `glossary`.

**Шумоподавление:**

- DeepFilterNet перед распознаванием и диаризацией, включён по умолчанию, с
  мягкой деградацией при недоступности движка.

**Качество стенограммы:**

- Разметка уверенности распознавания (`⚠`), схлопывание повторов, безопасная
  нормализация текста, пометка наложений (`⇄`), очистка неречевых артефактов
  (в том числе «голых» шумовых слов и шаблонных галлюцинаций) и опциональное
  автоисправление опечаток.
- Склейка подряд идущих коротких реплик одного говорящего в предложения.

**Экспорт и протокол:**

- Экспорт в TXT, DOCX, JSON и SRT с разметкой говорящих.
- Таймлайн «кто когда говорил».
- «Протокол» (резюме + стенограмма) формируется по кнопке; выгрузка
  стенограммы из веб-интерфейса.

**Интерфейсы:**

- **Веб-интерфейс** (`audio-transcriber web`; FastAPI + React SPA на
  `127.0.0.1`) — основной способ работы: очередь задач, загрузка и удаление
  файлов, число говорящих у задачи, живой прогресс по стадиям с длительностями
  и общим временем, стенограмма с поиском и метками, прослушивание фрагмента из
  реплики (HTTP Range), правка говорящих, «Применить имена», библиотека
  голосов, глоссарий, протокол, настройки и онбординг (баннер «Готовность» на
  основе `doctor`, авто-скачивание моделей, HF-токен как секрет, мастер первого
  запуска), светлая и тёмная тема.
- **CLI** на Typer: команды `transcribe`, `tui`, `web`, `glossary`, `doctor`.
- **TUI** на Textual: очередь, прогресс и поиск по стенограмме.
- Скрипты запуска `run.sh` / `run.ps1` / `run.bat` и `web.sh` / `web.ps1` /
  `web.bat`; Windows-обёртки синхронизированы с `run.sh`.

**Надёжность:**

- Постадийный кэш дорогих стадий (денойз/ASR/диаризация) и возобновление после
  сбоя: прогон, упавший на диаризации, при повторе переиспользует готовый ASR.
- `doctor` — самопроверка окружения, моделей и GPU-Vulkan (через
  `vulkaninfo`).

### Changed

- Версия хранится в единственном месте — в `pyproject.toml`; `__version__`
  читается из метаданных пакета, а не задаётся отдельно.
- TUI на Textual сохранён, но переведён во второстепенный путь: новые
  возможности развиваются в веб-интерфейсе.

### Fixed

- Чанкинг whisper.cpp устранён как причина потери текста и «шаблонных»
  галлюцинаций на длинных записях.
- Убрано лишнее перекодирование подходящего WAV (round-trip), из-за которого
  терялись куски аудио.
- Aligner больше не «угадывает» говорящего вслепую на больших разрывах
  разметки.
- При старте веб-сервера выполняется реконсиляция «осиротевших» задач очереди.
- История SSE очищается при повторном прогоне задачи.

### Architecture

- Движки вынесены за протоколы (`typing.Protocol`) для ASR, диаризации,
  объединения, экспорта, LLM и денойза — реализации взаимозаменяемы.
- Конвейер сборки и порядок вызовов — в `pipeline.py` (последовательный).
- TUI-приложение декомпозировано на модули (экраны, виджеты, сообщения,
  очередь, сборка конфигурации).
- Доменные модели не зависят от конкретных движков.

### Docs

- README с обзором, установкой, параметрами CLI, `config.env`, архитектурой и
  тестированием.
- Шаблоны `config.example.env` и `glossary.example.txt`.

### Tests

- 866+ тестов pytest: юнит-тесты, веб-API и интеграционный тест на реальном
  аудио.
- Ruff и mypy проходят без замечаний.
